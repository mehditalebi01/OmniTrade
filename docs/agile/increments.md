# Agile delivery plan and backlog

We use Agile XP as the main process. Lightweight backlog ordering, review, and
retrospective support planning. Each increment is selected from user stories
and follows conversation, acceptance examples, Red, Green, Refactor,
integration, acceptance, demonstration, and retrospective. The full rationale
is in `xp-selection.md`; the artifact and TDD record is in `xp-tdd-record.md`.

| Increment | Goal | Main stories | Planned hours | Definition of done |
|---|---|---|---:|---|
| I1 | Walking skeleton | US-01, US-02 | 20 | Owned browser-to-API path passes acceptance |
| I2 | Safe workflow design | US-03, US-04 | 28 | Invalid graph reasons and immutable publish pass |
| I3 | Event execution | US-05, US-06 | 34 | Parallel, event, pause/resume, and recovery acceptance pass |
| I4 | Trusted evidence | US-07, US-08 | 28 | Selected real evidence and quality-gate acceptance pass |

| I7 | Explainable product | US-13, US-14 | 22 | Role report, lineage, history, and GUI journey pass |
| I8 | Release evidence | US-15, US-16 | 16 | NFR gates, clean deployment, and evidence pack pass |
